# trino_grant_privileges Resource

Grants table privileges to a Trino user or role. Drift detection reads information_schema.table_privileges and therefore depends on Trino authorization. Use an admin identity for reliable results.

## Example Usage

```terraform
resource "trino_grant_privileges" "analyst_select" {
  privileges = ["SELECT"]
  on = {
    catalog = "hive"
    schema  = "sales"
    table   = "orders"
  }
  grantee      = "analyst"
  grantee_type = "ROLE"
  grant_option = false
}
```

## Import

Import is supported using the following syntax:

```shell
# Import a table privilege grant with
# <catalog>.<schema>.<table>:<grantee_type>:<grantee>.
terraform import trino_grant_privileges.analyst_select hive.sales.orders:ROLE:analyst
```

## Schema

### Required

- `grantee` (String) Principal receiving the privileges. This is an arbitrary Trino principal such as an LDAP DN or alice@example.com, not necessarily a SQL identifier.
- `grantee_type` (String) Grantee type: USER or ROLE.
- `on` (Attributes) Table the privileges are granted on. Changing it replaces the resource. (see [below for nested schema](#nestedatt--on))
- `privileges` (Set of String) Table privileges to grant. List SELECT, INSERT, UPDATE and/or DELETE explicitly. Drift detection reads information_schema.table_privileges and therefore depends on Trino authorization. Use an admin identity for reliable results.

### Optional

- `grant_option` (Boolean) Allow the grantee to grant these privileges to others (WITH GRANT OPTION). Updated in place.

### Read-Only

- `id` (String) Stable resource ID: <catalog>.<schema>.<table>:<grantee_type>:<grantee>.
