# trino_function Resource

Manages a catalog user-defined function. The connector backing the catalog must support UDF storage, as the Hive and Memory connectors do. Changing the definition replaces the function in place with CREATE OR REPLACE FUNCTION.

## Example Usage

```terraform
resource "trino_function" "add_one" {
  catalog    = "hive"
  schema     = "default"
  name       = "add_one"
  definition = "(x bigint) RETURNS bigint RETURN x + 1"
}
```

## Import

Import is supported using the following syntax:

```shell
terraform import trino_function.add_one catalog.schema.name
```

## Schema

### Required

- `catalog` (String) Catalog that stores the function.
- `definition` (String) SQL routine definition after the function name, starting with the parameter list, for example `(x bigint) RETURNS bigint RETURN x + 1`. This is raw SQL, not a value: identifiers inside it are not escaped by the provider. SHOW CREATE FUNCTION returns a normalised form; the provider compares definitions token by token so whitespace, keyword case and the parentheses Trino adds around RETURN expressions do not create diffs.
- `name` (String) Function name. Hive lowercases it; the configured spelling is kept in state.
- `schema` (String) Schema that stores the function.

### Optional

- `or_replace` (Boolean) Add OR REPLACE when creating the function. Defaults to false, so creating an existing function fails. Definition updates always use CREATE OR REPLACE because Trino has no ALTER FUNCTION.

### Read-Only

- `id` (String) Identifier in the form catalog.schema.name.
