# trino_view Resource

Manages a view. Trino stores the query in a normalised form, and Hive does not rewrite a stored view when an underlying column is renamed, so `definition` is write-only: state keeps the configured text and Read never overwrites it. Only `security` is read back and drifted. Changing the definition or the security mode runs CREATE OR REPLACE VIEW in place.

## Example Usage

```terraform
resource "trino_view" "orders_by_region" {
  catalog = "hive"
  schema  = "sales"
  name    = "orders_by_region"

  # Raw SQL placed after AS. Table references are resolved in the provider's
  # session, so qualify them fully.
  definition = "SELECT region, count(*) AS orders FROM hive.sales.orders GROUP BY region"

  # DEFINER (the default) runs the view with the definer's privileges;
  # INVOKER runs it with the querying user's.
  security = "DEFINER"
}
```

## Import

Import is supported using the following syntax:

```shell
# The definition is write-only, so it cannot be recovered from Trino on import.
# Supply it in configuration; the next apply runs CREATE OR REPLACE VIEW.
terraform import trino_view.orders_by_region hive.sales.orders_by_region
```

## Schema

### Required

- `catalog` (String) Catalog that stores the view.
- `definition` (String) SELECT statement placed after AS. This is raw SQL, not a value: identifiers inside it are not escaped, and table references are resolved in the provider's session catalog and schema, so qualify them fully. Write-only: SHOW CREATE VIEW returns a normalised form, and Hive keeps a stale definition after an underlying column rename, so state keeps the configured text instead of pretending to detect definition drift. Changing it runs CREATE OR REPLACE VIEW.
- `name` (String) View name. The provider always quotes it. Hive lowercases it; the configured spelling is kept in state and the stored spelling is resolved case-insensitively, because a quoted SHOW CREATE VIEW rejects a non-lowercase name.
- `schema` (String) Schema that stores the view. Hive lowercases it; the configured spelling is kept in state and the stored spelling is resolved case-insensitively.

### Optional

- `security` (String) View security mode: DEFINER runs the view with the definer's privileges, INVOKER with the querying user's. Defaults to DEFINER. Read parses the SECURITY clause from SHOW CREATE VIEW, so an out-of-band change is detected. Changing it runs CREATE OR REPLACE VIEW.

### Read-Only

- `id` (String) Identifier in the form catalog.schema.name.
